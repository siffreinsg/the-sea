# Plan — LLM stack: LiteLLM + Open-WebUI (Thriller Bark)

One plan, two stacks — they're only useful together. Follows
`docs/runbooks/add-a-service.md`; deltas only. Delete this doc when both land.

**Shape:** LiteLLM is the single gateway; **Open-WebUI and n8n both point at it** so
keys and cost tracking stay in one place. **Hosted APIs only, no Ollama** — TB is ARM
and CPU-only. Call logging and cost go to the existing Grafana/Loki; **LangFuse is
dropped** (Clickhouse + MinIO + Redis + Postgres is not worth it when the
observability stack already exists).

Pin both images to the current released tag at implementation time, and read that
version's docs — both projects move fast and their config schemas move with them:

```bash
r=open-webui/open-webui   # and berriai/litellm

curl -s -H "Authorization: Bearer $t" "https://ghcr.io/v2/$r/tags/list?n=1000" | jq -r '.tags[]'
```

## 1. LiteLLM — deploy first

**Node TB.** Bind `127.0.0.1:4000`. **No Caddy route, no Authelia** — it's internal,
authenticated by its own API keys, and nothing outside TB needs it. This is the one
app in the fleet that stays off the edge entirely; don't "helpfully" add a route.

- Config is a YAML model list (provider, model name, `api_key` as an env reference) —
  plain committed file, bind-mounted, so the stack needs
  `extra_args = ["--force-recreate"]`.
- Provider API keys and the LiteLLM master key into `secrets.env`. Never in the YAML.
- **Skip the Postgres-backed admin UI / virtual-key store unless you actually want
  per-key budgets.** The config-file-only mode needs no database, which means no dump,
  no plan entry, no restore path. Add the DB later only if budgets become a real need.

## 2. Open-WebUI — after LiteLLM answers

**Node TB.** Bind `127.0.0.1:3020` — **not** 8080, that's headscale. TB's taken ports:
8080 headscale, 9091 authelia, 9120 komodo, 9898 backrest, 5006 actual, 5678 n8n,
12345 alloy. Host `chat.siffreinsigy.me`. Fresh build: the legacy
`docker-mei/open-webui/webui` dir was **deleted intentionally** and is not in the
archive, so there is nothing to restore.

- Points at LiteLLM as an OpenAI-compatible backend (`OPENAI_API_BASE_URL` →
  `http://127.0.0.1:4000/v1`, key = a LiteLLM virtual/master key). Verify the exact
  env var names against the pinned version.
- Default Postgres/SQLite: **SQLite is fine** for a single user — one less container,
  one less dump.

### Auth — OIDC

Open-WebUI supports OIDC, so per §3b(a) it gets a real Authelia client, not
forward-auth. New client in `thriller-bark/authelia/secrets.oidc.yml`
(`client_id: open-webui`, hashed secret, explicit `redirect_uris` — **set the callback
explicitly, don't trust auto-derivation**, the lesson from Dawarich).

Set it to **not** auto-create accounts beyond the single user, and disable the local
signup path, mirroring what Dawarich does (`OIDC_AUTO_REGISTER`-equivalents — check
the pinned version's names). Single user by config, not by hope.

### n8n wiring

Once LiteLLM is up, point n8n's LLM nodes at `http://127.0.0.1:4000/v1` with their own
LiteLLM key — same host, so no mesh hop. This is the reason LiteLLM exists; don't skip
it and let n8n hold provider keys directly.

## Backups

- **LiteLLM:** nothing, if it stays config-file-only (config is in git, keys in SOPS).
  If the Postgres key-store is added later, it needs a `backup.sh` and a **critical**
  plan entry.
- **Open-WebUI:** its data volume holds chat history and settings → `backup.sh` if it
  ends on Postgres, otherwise mount the volume `:ro` into TB's Backrest and add it to
  the **bulk** plan. Chats are not critical data.

## Done when

Open-WebUI logs in via Authelia with no local-signup path left open, a chat completes
through LiteLLM, an n8n node completes through the same gateway, and LiteLLM has no
public route.
