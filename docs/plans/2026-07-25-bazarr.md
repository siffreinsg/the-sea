## Media access — rclone SFTP mount

**Task 0 is resolved and the plan is simpler for it.** Sunny doesn't run Tailscale at
all — it doesn't need to. Its SSH/SFTP is reachable from GM on port 22 over the public
internet (verified), so the mount has **no mesh dependency**: no `After=tailscaled`
ordering, no userspace-tailscale inbound-bridging problem, nothing to test first.

A prior rclone mount was abandoned because it went **stale**, a maintenance problem,
not an incompatibility. FUSE is confirmed working in a container on GM's OpenVZ kernel
(`FUSE_OK` passed). Komodo's image-update polling is what fixes the root cause, so:

- A **Komodo-managed `rclone` container** mounting Sunny over SFTP at its public
  address, bind-mounted rw into Bazarr.
- SFTP credentials into `secrets.env` — **prefer an SSH key over a password**, since
  this connection crosses the public internet rather than an encrypted mesh. Restrict
  the key to Sunny if Ultra.cc allows it.
- **Fallback if mount propagation into the container misbehaves on OpenVZ** (now the
  only real risk left): a host `systemd` rclone mount unit, bind-mounted into Bazarr
  normally.

## Path mapping — the make-or-break step, and it stays blocked

**Not pre-writable.** The table needs the real library roots as Sonarr/Radarr report
them on Sunny, and the real mount point on GM — neither is knowable without a live
look at both. Any path written here ahead of time would be a plausible guess that
reads as fact. Do it at the console:

1. On Sunny's Sonarr/Radarr: Settings → Media Management → root folders. Write the
   exact strings down.
2. On GM after the mount is up: `ls` the mount and find the same trees.
3. Fill Bazarr's mapping table from (1) → (2).


Sonarr/Radarr report **their** paths; Bazarr sees the same files at a different path
under the mount. Bazarr's path-mapping table has to translate between them or
subtitles are written into the void with no error. Get one episode end-to-end before
declaring this done.

Connect to Sonarr/Radarr over their **public direct-connect URLs** (the
PlexAutoLanguages/Profilarr pattern), not mesh addresses.

## Auth

**Forward-auth** — Bazarr has no OIDC. Plain single-branch block, no bypass paths
needed (the arr apps talk to Bazarr, not the reverse; if that turns out false, bypass
`/api/*` with the `handle {}`-per-branch rule from §3b).

## Backups

Config dir is cold state (SQLite + provider settings). Mount `:ro` into GM's Backrest,
add to the GM **bulk** plan. Not critical.

## Done when

The mount survives a GM reboot, one subtitle lands on disk at the path Sonarr expects,
and the config volume is in a GM bulk snapshot.
