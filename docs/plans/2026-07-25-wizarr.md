## Auth — native, with bypasses

Wizarr has its own admin login and authenticates end users through Plex. Guests must
reach the invite pages **without** hitting the Authelia portal, so forward-auth
protects the admin surface only.

**Path list read off the source at `v2026.7.1`** (`app/blueprints/__init__.py` plus each
blueprint's `Blueprint(url_prefix=…)` and `@route`), checked 2026-07-25. Per §3b(b),
with every branch in its own `handle {}`:

```caddyfile
	@wizarr host wizarr.siffreinsigy.me
	handle @wizarr {
		# public_bp has no url_prefix; wizard_bp is url_prefix="/wizard".
		@wizarr_public path /j/* /join /invitation/process /reset/* \
		                    /wizard /wizard/* /static/* \
		                    /health /favicon.ico /image-proxy /cinema-posters
		handle @wizarr_public {
			reverse_proxy host.docker.internal:15690
		}
		handle {
			forward_auth authelia:9091 {
				uri /api/authz/forward-auth
				copy_headers Remote-User Remote-Groups Remote-Email Remote-Name
			}
			reverse_proxy host.docker.internal:15690
		}
	}
```

Two things that list gets right and the earlier guess did not:

- **`/setup*` is deliberately NOT public.** It's the first-run admin bootstrap
  (`setup_bp`, `url_prefix="/setup"`). Behind Authelia. The old draft would have
  exposed it.
- **`/wizard/*` is safe to expose** even though it's post-redemption onboarding:
  `wizard_bp.before_request` (`restrict_wizard`) re-validates the invite code on
  *every* request and allows only authenticated users or a live invited session.
  Wizarr enforces it; the edge doesn't have to.

Test both sides explicitly: an invite URL in a private window must render for an
anonymous visitor, and both `/` and `/setup` must 302 to the portal.
