## Config

Homepage's config is a set of YAML files (`settings`, `services`, `widgets`,
`bookmarks`) — so they belong in git as **plain committed files**, bind-mounted, the
same shape as Authelia's `configuration.yml`. Bind-mounting git-tracked files means
the stack needs `extra_args = ["--force-recreate"]` (inode pinning — see
`domains/deploy.md`).

API keys for service widgets (arr stack, Plex, Backrest…) go in `secrets.env` and are
referenced from the YAML as `{{HOMEPAGE_VAR_*}}`. **Convention confirmed** in
`docs/installation/docker.md` at v1.13.2: env vars must be prefixed `HOMEPAGE_VAR_` or
`HOMEPAGE_FILE_`, and `HOMEPAGE_VAR_XXX` substitutes `{{HOMEPAGE_VAR_XXX}}` in any
config file. Never inline a key in the YAML.

`HOMEPAGE_ALLOWED_HOSTS=dash.siffreinsigy.me` — required since v1.0 for any host other
than localhost, and the single most common "why is it blank" failure. If it errors,
the logs print the host string it actually saw; match that exactly (it may include a
port). **Do not set it to `*`** — upstream's own docs call that out as not recommended.

The container **runs as root by default**; `PUID`/`PGID` are supported to drop that.
Set them, and make sure the bind-mounted config dir matches
(`docs/installation/docker.md`, v1.13.2).

Start with a small config and grow it: the fleet's own services first (Grafana,
Komodo, Backrest ×2, Authelia, Dawarich, Actual, n8n, Profilarr, your_spotify), Sunny's
media stack second. Widgets are optional per service — a plain link is fine.

## Auth

**Forward-auth**, single branch, no bypasses. Homepage has no OIDC and no user model;
it's a launcher, so the Authelia cookie is the whole access story.

## Backups

**Nothing to back up** — all config is in git and the container holds no state. This
is a deliberate skip, not an oversight.

## Done when

The dashboard renders behind the Authelia gate, every listed service link resolves,
and a config edit pushed to git shows up after a Komodo deploy (proving the
force-recreate is doing its job).
